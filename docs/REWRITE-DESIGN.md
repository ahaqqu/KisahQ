Status: DESIGN + PROOF-OF-CONCEPT (issue #8, owner decision 2026-11-12).
Evidence in this branch: `compositions/poc.html` renders to a byte-deterministic MP4 on this laptop. The old DOM interactive engine retires; stories become baked videos; the app becomes a video library.

**Font truth (correction of an earlier "bundled Nunito" claim):** the POC's rounded look is NOT a bundled font. No Nunito/Poppins font file exists on this machine (exhaustive `fc-list` + filesystem search), the pinned chrome-headless-shell 152.0.7977.30 bundles no fonts, and hyperframes bundles only Inter / JetBrains Mono / EB Garamond presets. `"Nunito"` / `"Poppins"` in the composition font stack resolve through a machine-local fontconfig substitution. Same-machine determinism is unaffected (renders stay byte-identical), but typography is currently fontconfig luck and would drift on another machine — PR-B MUST commit real `@font-face` fonts to close this (see §7 and §9.6).

Extrapolation for the target catalog: a ~90 s story ≈ 90–135 s per render; 2 languages × 2 stories ≈ 6–9 min total on this laptop (i7-8550U, 8 cores). CI smoke test (one 12 s composition) fits comfortably in a CI window.

Stack facts verified from primary sources (repo README + shipped agent skills + `packages/*/src`, not summaries):

- **License:** Apache-2.0. No per-render fees, no commercial thresholds.
- **Node:** `>=22` (local v26.13.0 OK). **FFmpeg 9** found on PATH; overridable via `HYPERFRAMES_FFMPEG_PATH` / `HYPERFRAMES_FFPROBE_PATH`.
- **Packages:** `hyperframes` (CLI, devDependency; bundles core/engine/producer/parsers/lint) is the **minimum renderer-only install**. Published family: `@hyperframes/core`, `@hyperframes/engine`, `@hyperframes/producer`, `@hyperframes/studio`, `@hyperframes/player`, `@hyperframes/shader-transitions`, `@hyperframes/aws-lambda` — none needed for our pipeline.
- **Composition format:** HTML file, `#root[data-composition-id]` with `data-start` / `data-duration` (seconds) / `data-width` / `data-height` / `data-fps`; timed elements carry `class="clip"` + `data-start` + `data-duration`; each composition registers ONE paused GSAP timeline as `window.__timelines["<composition-id>"]` after its tweens; `fromTo` only (seek-back drift), never `repeat: -1`, never `Date.now()` / unseeded `Math.random()` / mid-render fetches.
- **Audio tracks:** `<audio id="..." class="clip" data-start data-duration? data-volume? data-fade-in? data-fade-out? data-media-start? src="assets/...">` — every `<audio>` needs an `id` or it is excluded from the mix; producer mixes at encode (FFmpeg), gain up to +12 dB, `data-automation` envelopes supported.
- **Telemetry:** usage counters, disable with env `HYPERFRAMES_NO_TELEMETRY=1` — set in every script and CI job (zero-telemetry canon).
- **Version freeze:** with only the telemetry opt-out set, an attended (non-CI, TTY) run still performs update checks and can background-install silent 0.9.x upgrades (`scheduleBackgroundInstall`) — the CLI can mutate itself between runs. The render-standard env is therefore **`HYPERFRAMES_NO_TELEMETRY=1 HYPERFRAMES_NO_AUTO_INSTALL=1 HYPERFRAMES_NO_UPDATE_CHECK=1`** in every attended script and environment; CI is already safe via its own isCI gate. `scripts/render-stories.mjs` (PR-B) exports all three.
- **Determinism contract:** frame clock = `floor(frame)/fps` integer math; GSAP timelines seeked, never played; capture via `HeadlessExperimental.beginFrame` (needs chrome-headless-shell — `npx hyperframes browser ensure` downloads a version-pinned build, keeping pixel output stable across runs on one machine).

## 1. Composition anatomy for KisahQ stories

One generated composition file per story per language: `compositions/<slug>-<lang>.html` (e.g. `berbagi-rambutan-id.html`, `berbagi-rambutan-en.html`). Generated by `scripts/build-compositions.mjs` from `stories/<slug>/story.json` + `src/art/*` — committed, diffable, hand-tweakable (regeneration overwrites; hand edits must be followed by regeneration discipline or moved into the builder).

Timeline shape (berbagi-rambutan has 9 beats, truk has 11; target total 60–100 s):

```html
<div id="root" data-composition-id="berbagi-rambutan-id" data-start="0"
     data-duration="74.5" data-width="1280" data-height="720" data-fps="30">
  <!-- 1. Title card (always first beat): story title ID/EN + kisah logo chip -->
  <div id="beat-title" class="clip" data-start="0" data-duration="4.2" data-track-index="1">…</div>

  <!-- 2. One scene host per story beat, sequential, no gaps -->
  <div id="beat-pembuka"  class="clip" data-start="4.2"  data-duration="7.6" data-track-index="1">…</div>
  <div id="beat-teman-salam" class="clip" data-start="11.8" data-duration="6.9" data-track-index="1">…</div>
  <!-- … -->
  <div id="beat-penutup"  class="clip" data-start="66.8" data-duration="7.7" data-track-index="1">…</div>

  <!-- 3. Hikmah card (always last beat): hikmah + reflection prompt -->
  <div id="beat-hikmah" class="clip" data-start="74.5" data-duration="6" data-track-index="1">…</div>

  <!-- Narration audio, one per beat, absolute start aligned to its beat -->
  <audio id="vo-pembuka" src="assets/voice/berbagi-rambutan/id/pembuka.mp3"
         data-start="4.35" data-volume="1"></audio>
  <!-- Gamelan stingers + SFX on their own tracks -->
  <audio id="stinger-open" src="assets/sfx/gamelan-open.mp3" data-start="0" data-volume="0.7"></audio>
</div>
```

Per-beat structure inside a scene host ( Bold Flat Pop, 1280x720, action-safe 90%):

- **Background layers:** the beat's `bg` key → 3 static SVG layers (`bg-layer--far/mid/near`) from `renderBackground(key)` (orchard for story 1; kamar-ezra / ruang-tamu for story 2), absolutely stacked `inset: 0`. A slow 2–4 s drift tween (finite, `yoyo`) replaces the old pointer parallax.
- **Actors:** each `{character, pose}` → the character's rendered SVG (Qila/Ezra from `renderQila/renderEzra`; Toto/Lili/Nana/Momo from `CHARACTERS`), placed on the teal ground band; entrance tween per actor (fade+rise 0.5 s) and a finite idle bounce.
- **Expression beats:** pose → expression chip map preserved (`DEFAULT_QILA_EXPRESSION` / `DEFAULT_EZRA_EXPRESSION` from `src/art/qila-ezra.ts`): Qila hijab ALWAYS rendered (canon, in `qilaHijab()`); Ezra lesung pipi in EVERY render (`ezraDimples()`), explicitly checked for smiling shots (e.g. `ketemu-truk` uses `grin-with-dimples`).
- **Narration caption:** large toddler-readable caption line at bottom (80% title-safe), karaoke-style word highlight driven by the TTS word-boundary timings (see §3) baked into the composition as GSAP tweens.
- **Prop cues:** story-2 props (`renderTruk({hidden})`, `renderPetaMainan()`, `renderRumahTruk()`) enter/exit on narration cues; story-1 count beat (`hitung-buah`) renders five rambutan SVGs popping in one-by-one (0.4 s apart) with the counting narration.
- **SFX:** each scene's `sfx` value → stinger audio clip at the beat's cue point (§3).

Root-level conventions:

- First beat is always a title card; last beat is always the hikmah card carrying `data-hikmah-id` / `data-hikmah-en` attributes (the CI validator reads them; ID/EN parity = both files exist, each carries its language's hikmah verbatim from story.json).
- Beat durations come from the narration audio length per language (build script ffprobes the MP3s → beat duration = narration + 0.9 s pad, min 5 s), so ID and EN timelines differ slightly — correct, because each language gets its own file and render.
- Language of captions/title/hikmah inside the file is fixed (per-language file, no runtime variables needed for the pipeline; `--variables` stays available for one-off variants like a name-personalized render later).

## 2. Art pipeline (src/art/*.ts → composition markup)

`scripts/build-compositions.mjs` (Node, run with `tsx` devDep so it can import the TS art modules):

1. Read `stories/<slug>/story.json` (+ `characters/*.json` for expression chips).
2. Per beat, call the existing pure SVG-string builders — `renderBackground(bg)`, `renderQila(pose, expression)`, `renderEzra(pose, expression)`, `CHARACTERS[actor].render(pose)`, `renderTruk/renderPetaMainan/renderRumahTruk`, motif helpers — and inline the returned SVGs into the beat host markup (inline SVG, no external asset requests: determinism rule "no fetching mid-render" and CI-offline both satisfied).
3. Generate the GSAP block: entrance/idle/caption tweens per beat with absolute times computed from the narration durations, registered as `window.__timelines["<slug>-<lang>"]`.
4. Write `compositions/<slug>-<lang>.html`. Output is deterministic (no timestamps in the file; git diffs are clean).

Character canon guardrails stay in the art modules (single source of truth), so the composition can never de-render the hijab or dimples — they are properties of `renderQila` / `renderEzra`, not of the beat markup. `tests/canonical-art.test.ts` (new) greps generated compositions for `qez-hijab` in every Qila beat and `qez-dimples` in every Ezra beat.

## 3. Audio

**Narration — edge-tts at authoring time, committed MP3s** (matches the existing baked-audio convention from `scripts/generate-audio.mjs`):

- Tool: devDep **`@andresaya/edge-tts` 1.9.1** (pure Node/TS, works on bun, **1.1 s per line** on this machine, returns word-boundary timestamps). Python `edge-tts` via `uvx` verified as fallback (id-ID-ArdiNeural + id-ID-GadisNeural listed; ~2–3 s/line steady-state; 9 s incl. cold start). npm alternative landscape checked: `node-edge-tts` (2026-10), `@bestcodes/edge-tts` — @andresaya chosen for TS types, word boundaries, and active maintenance.
- Voices: ID = `id-ID-ArdiNeural` (male, friendly) or `id-ID-GadisNeural` (female) — pick one narrator per story (default Ardi); EN = `en-US-EmmaMultilingualNeural` (verified working, can also cover ID if a single voice is ever preferred).
- Output: `assets/voice/<slug>/<lang>/<beat>.mp3` (24 kHz mono 48 kbps, ~10–25 KB per line) — **committed** (small, keeps CI deterministic and renders reproducible without network; total repo impact for 2 stories ≈ 40 lines × ~18 KB ≈ 0.7 MB).
- Word boundaries → per-word caption karaoke tweens in the generated composition (exact timing, not the old word-count estimate).
- Upgrade path unchanged: `GOOGLE_TTS_KEY` / `ELEVENLABS_KEY` providers in `scripts/generate-audio.mjs` re-render better voices when the owner adds keys (MANUAL_ACTIONS entry at that point).

**Gamelan stingers + SFX — rendered audio files:**

- The WebAudio synth (`src/engine/sfx.ts`: paired slightly-detuned sine plucks with exponential decay, filtered-noise whoosh) is runtime JS — HyperFrames compositions can't run it deterministically. Port the same synth math to pure Float32 PCM generation in `scripts/render-stingers.mjs` (no WebAudio needed: oscillators → sample math → ffmpeg encode) producing `assets/sfx/{chime,pluck,shake,whoosh,pop,sparkle}.mp3` + `assets/sfx/gamelan-{open,close}.mp3`. Deterministic, committed (each ~5–20 KB).
- Placement: title card gets `gamelan-open`, hikmah card gets `gamelan-close`, per-scene `sfx` value plays at its beat's cue with `data-volume="0.6"`. Narration ducking not needed (stingers sit between narration lines).

## 4. Render pipeline

`scripts/render-stories.mjs` (Node; wraps the HyperFrames CLI):

```
node scripts/render-stories.mjs [slug] [--lang id,en] [--quality looks]
  per slug × lang:
    1. validate composition (scripts/validate-compositions.mjs gate)
    2. HYPERFRAMES_NO_TELEMETRY=1 HYPERFRAMES_NO_AUTO_INSTALL=1 HYPERFRAMES_NO_UPDATE_CHECK=1 npx hyperframes render
         -c compositions/<slug>-<lang>.html -o videos/<slug>/<lang>.mp4
         --fps 30 --quality looks     (delivery for the final pass)
    3. poster: ffmpeg -ss <title-hold> -i <mp4> -frames:v 1 videos/<slug>/<lang>.jpg
    4. verify: ffprobe duration ≈ root data-duration, resolution 1280x720, size < 25 MB
```

- `videos/` is **gitignored**. Artifacts go to **R2**: `videos/<slug>/<lang>.mp4` + `videos/<slug>/<lang>.jpg` (poster).
- **R2 layout + delivery (decision point, §9):** `wrangler r2 object put kisahq-videos/videos/<slug>/<lang>.mp4 --file …` from the laptop deploy path; the bucket is exposed read-only at `cdn.kisahq.ahaqqu.com` (public bucket custom domain — keeps the "no worker script, zero server logic" property of the deploy) — recommended. The issue text's alternative (streamed via a Worker route) adds a worker script + server logic to an intentionally assets-only Worker; flagged for owner confirmation.
- **Size math:** ~526 kbps measured → ~90 s video ≈ 5.9 MB/lang/story → 4 videos ≈ 24 MB total in R2 (free tier: 10 GB-month). Workers static assets' 25 MiB/file limit would technically also hold these files, but bundling videos into the deploy bloats every deploy and mixes artifacts with code — R2 stays the plan.
- Upload step records MANUAL_ACTIONS entry (R2 bucket creation + custom domain attach are owner/one-time console actions) or runs under an R2-scoped API token in CI.

## 5. CI gates

1. **Composition validator** — `scripts/validate-compositions.mjs` (Zod, wired into `package.json` as `validate:compositions` and run by CI on every PR):
   - every `compositions/<slug>-<lang>.html` has: root `data-composition-id` = slug+lang, `data-duration` ≥ last beat end, `data-width=1280`, `data-height=720`, `data-fps=30`;
   - hikmah parity: for each slug, BOTH `-id.html` and `-en.html` exist and each carries `data-hikmah-id` / `data-hikmah-en` matching `story.json` verbatim;
   - every `<audio>` has an `id` and its `src` exists on disk; every referenced asset path exists; every beat's narration audio covers ≥ half its beat;
   - clip end ≤ root duration; no `<template>` wrapper on standalone compositions; timeline registration present (`window.__timelines["<id>"]`);
   - canon greps: `qez-hijab` in every Qila beat, `qez-dimples` in every Ezra beat.
2. **Render smoke test** — CI job (ubuntu runner): `npx hyperframes browser ensure`, then render `compositions/poc.html` (12 s, no assets) with `--quality draft`; assert exit 0, wall-time < 180 s, output 1280x720 h264, size < 10 MB, ffprobe duration within 0.1 s of 12.0. Runs on PRs touching `compositions/**` or `scripts/render-*`.

## 9. Open risks & decisions for the owner

1. **Render time on laptop:** measured 1.0–1.5x realtime at 720p30. A 4-story × 2-language catalog re-render ≈ 6–9 min — fine. At 1080p or 60 fps it doubles; stay at 720p30 (toddler tablets; matches POC).
2. **R2 delivery shape (decision):** recommended public R2 bucket + `cdn.kisahq.ahaqqu.com` custom domain (zero worker script, preserves "assets-only Worker" deploy property) vs the issue's "streamed via Worker route" (adds a worker script + server logic). Needs owner sign-off either way; both use the same `videos/<slug>/<lang>.mp4` layout.
3. **Edge-tts endpoint reliability:** keyless Microsoft endpoint, no SLA; occasional 403/latency spikes are reported upstream. Mitigations: narration is authoring-time only (a flaky endpoint never breaks CI or runtime), MP3s are committed, Python `uvx edge-tts` fallback verified, Google/ElevenLabs upgrade path wired via MANUAL_ACTIONS when keys exist.
4. **HyperFrames version churn:** 0.9.x moves fast (0.9.34→0.9.35 within days). Pin exactly in devDeps; render script asserts the installed version matches the lockfile; treat minor bumps as opt-in re-render events. Attended runs also set `HYPERFRAMES_NO_AUTO_INSTALL=1` / `HYPERFRAMES_NO_UPDATE_CHECK=1` (§0 render standard) so the CLI cannot background-upgrade itself between runs; CI is safe via its isCI gate. Determinism is per-machine; if a cross-machine re-render ever matters, `render --docker` pins the whole toolchain (Docker 29.9.2 present).
5. **Repo-root `index.html` collision:** HyperFrames' project commands (`check`, `preview`) treat repo-root `index.html` as a root composition, which is the Vite app's file — they collide. Mitigation in PR-A: per-composition `render -c` / explicit file linting (POC path, works today); if Studio preview becomes wanted later, a dedicated `video/` subproject directory is the escape hatch. Flagged so PR-A doesn't silently break `hyperframes check`.
6. **Typography is fontconfig substitution until PR-B commits real fonts:** no Nunito/Poppins file exists on the render machine (exhaustive `fc-list` + filesystem check); the pinned chrome-headless-shell bundles no fonts; hyperframes bundles only Inter / JetBrains Mono / EB Garamond. `"Nunito"` / `"Poppins"` render via a machine-local fontconfig substitution — same-machine renders stay byte-identical, but the look is luck across machines. **PR-B MUST commit real `@font-face` fonts (e.g. Nunito woff2 under `assets/fonts/`) for deterministic typography.** Latin-script ID/EN text is covered once fonts are committed; any future Arabic-script text (e.g. full bismillah calligraphy) additionally needs an Arabic-capable font file.
